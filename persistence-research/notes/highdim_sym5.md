# Sym5: deeper decimal pins on the final 95 sym4 configurations

This is a bounded computational continuation, not a proof of the general
multiplicative-persistence conjecture. Dimension is one plus the number of far
digits. The input is exactly the 95 keys in `sym4/summary.json`'s `open` list:
94 for target 14112 and one for target 32. All writes are restricted to
`verification/highdim/sym5/` and this note. No commit is made. Python is run with
`bash -c 'ulimit -v 8000000; python3 -I ...'`, using only the standard library,
at most ten simultaneous workers, bounded commands, and atomic checkpoints.

## Proof of the deeper pin

Write

\[
X=10^L+K+\sum_i c_i10^{q_i},\qquad
t_0=v_2(K),\quad K_0=K/2^{t_0},\quad Y=X/2^{t_0}.
\]

The certificate domain has distinct positions `qmin <= q_i < L`; for no far
digits it has `L >= qmin`. The existing requirement `qmin > t0` proves
`v2(X)=t0`, so Y is an odd integer. Let `0 <= k <= qmin`. Every variable
decimal term, including `10^L`, is divisible by `10^k`; hence
`X = K (mod 10^k)` throughout the domain. A position **equal** to `qmin=k`
causes no exception: its term still contains the full factor `10^k`. The
same is true of `L=qmin` in dimension one. Distinctness is not needed for
this congruence; relaxing collisions while sieving remains safe.

Divide **once** by `2^t0`. The 5-part is unchanged because 2 is a unit
modulo `5^k`. If `k>t0`, the 2-part becomes `2^(k-t0)`. If `k=t0`, it
becomes 1. If `k<t0`, integrality of Y and K0 supplies no further 2-adic
restriction from the decimal pin, so it is also 1. Thus in all cases

\[
Y\equiv K_0\pmod{D_k},\qquad
D_k=5^k2^{\max(k-t_0,0)}.
\]

For k=0 there is no decimal restriction. There is no second division of
either K0 or the modulus. In particular, imposing `2^k` on Y without the
division can exclude true smooth values. A weaker modulus obtained by
dividing the 2-part twice is not an unsound exclusion by itself, but loses
strength and is not the claimed congruence.

For a smooth X, `Y=3^a7^w`. Independently enumerate the cycles of 3 and 7
modulo Dk, of lengths A,W, and retain **every** pair `(ar,wr)` with
`3^ar7^wr=K0 (mod Dk)`. Since 3 and 7 are units, these cycles enumerate
all exponent residue classes. Exact signatures filter the corresponding
residue; free signatures move by A or W. At an auxiliary prime these steps
generate a subgroup, and each retained pair supplies one allowed coset.
No lower bound removes an element from a free arithmetic progression's
image in the finite group. This is exactly the existing audited kill, with
a stronger domain-wide necessary congruence.

When pin2 is enabled, the separate condition `qmin >= t0+3` proves
`Y=K0 (mod 8)`. Filtering the tail pairs by this parity constraint is valid:
for k>=1, Dk contains 5, and the orders of both 3 and 7 modulo 5 are even,
so adding A,W does not alter exponent parity. For k=0 the existing separate
pin2 branch is retained. Both constraints refer to the same K0.

## Implementation and tests

`gen_sym.py` and `check_sym5.py` are copies of sym4's generator and checker.
Their marked diffs are adjacent `.diff` files, reproducibly generated by
`setup_sym5.py`. The generator now rejects a requested depth above qmin
instead of silently clamping it; its modulus formula was already correct.
The checker removes only the depth-three cap and replaces quadratic cycle
membership and Cartesian pair scanning with a set and an exact inverse
lookup join. Every representative is retained, including repeated residues
in the 7-cycle lookup. No arithmetic kill or refinement rule changes.

The copied search driver raises its slice floor to at least the requested k
and explicitly partitions the omitted low positions. It never uses a deeper
pin on the unsplit original domain. The copied position-cover auditor
independently replays these partitions. Reusing sym4 pieces is a search
optimization. New certificates are directly checked. For inherited sym4
certificates, existing M/F PASS records may be reused from
`sym4/dual_checks.json` only with identical certificate hash, checker hash,
and brute bound. The original M checker directly verified these k<=3
certificates; their semantics are unchanged by the depth-cap extension.
The full original CLI records and their source
ledger are retained. Every new certificate receives a fresh sym5 replay.
One attempted fresh F replay timed out at 180 seconds; this is a resource
outcome, not a counterexample, and the unchanged certificate's existing F PASS
is still valid. Downgraded k=3 certificates are new and receive fresh F replays.

Executed `test_sym5.py`: **PASS**, 168 planted smooth instances, 10,752
class/prime tests, **zero false kills**. k ranges from 1 through 6; t0 ranges
over 0,1,2,3,4,6,8. The cases include k<t0 (68), k=t0 (20), and k>t0 (80),
positions at the floor, dimension-one L at the floor, and pin2 on/off.
Generator and checker period/pair sets agree; for k<=3 an additional direct
Cartesian enumeration agrees too. The correctly recorded genuine exact-size
solution is accepted. The explicit over-pin is rejected by both constructors.
A generator mutation that uses `5^k*2^k` on Y produces a false prime kill
of a planted true solution; the correct checker rejects that certificate.
The low-position split controls also pass: 72 labelled cases/780 points,
and 72 position-partition cases/585 canonical points.

Certificate validation and search results are recorded below after the
checkpointed runs finish. Deep certificates are listed in
`verification/highdim/sym5/deep_pin_certs.txt` for the independently extended
F5 checker. Original F is used without modifications on certificates at
depth at most three. A failed replay or an incomplete cover is never a
closure.
