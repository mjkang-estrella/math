# Source and dependency reproduction

The ordinary verification path needs Python 3's standard library only; no network, Lean, TeX or external paper downloads. Invoke the scripts with `python3 -I` (their sibling import path is installed explicitly). Assertions stay enabled for the historical finite programs. `reproduce_finite.py` makes temporary copies, runs the manuscript's exact audited `support/reproduce.py`, compares full finite outputs and all receipt fields except interpreter version, and removes the copies. `verify_bundle.py` checks the exact selected archive and the complete frozen formal-review package; omitted historical inputs are not fetched or silently treated as verified.

The original author formal verifier `staircase-formal-v1/verify.py` checks live full project-relative input paths, including files not publicly selected. It is retained for provenance and is not promised to pass in an arbitrary extraction. The proof review's live audit/verifier and manuscript historical audit/build/freeze tools likewise retain their original contracts. The portable bundle verifier replaces none of their historical conclusions; it verifies selected-byte integrity and the stated frozen formal evidence.

The independent `staircase-formal-review-r1/verify_review.py` defaults to frozen `author-copy/` files and `context/main.tex`. That complete inventory is included, so its default verification works in the clean selected extraction. `--live-inputs` additionally requires the original 28 live input paths and is not the portable public command. The original `run_review.py` has a review-relative cache default and NO `--cache` or `--lean` option. Do not claim its raw CLI is portable to an extraction.

`rebuild_lean.py` solves that path setup explicitly. It copies the complete selected author/review packages into a disposable tree under this release directory, runs the exact author `rebuild.py --lean ... --cache ...`, loads the exact copied independent `run_review.py` bytes as a Python module, overrides that module's `LEAN` and `CACHE` path constants in memory, and invokes its unchanged `main()` with its normal no-option full audit. It checks that the function globals and copied `HERE` are correct before running. Frozen source/receipts are never modified. The wrapper returns fresh receipts on stdout and deletes its temporary tree. Independent receipts include elapsed times, so new receipts are not asserted byte-identical to the frozen ones. Use the recorded frozen verifier before a rebuild, not after overwriting frozen artifacts.

Required compiler: Lean 4.34.1, commit `5045d0056413266e57c625dcd7c365b10e377c52`. Required mathlib: `d13f23b723b8a846827a245b89c10fc7d3f11612`. `lean-rebuild.json` and the unmodified `lake-manifest.json` list all nine exact dependency revisions and their original repository URLs. Provide an existing `--cache /absolute/path/to/.lake/packages` containing those nine Git checkouts at those exact HEADs, with usable compiled mathlib and imported-dependency oleans under each package's `.lake/build/lib/lean`. Provision that cache separately using the pinned Lean/Lake toolchain and lockfile, following the dependency projects' own build instructions/licenses; this task does not download or build dependencies. The wrapper rejects absent/mismatched checkouts and missing compiled mathlib. It constructs `LEAN_PATH` through the original audited runners, with the newly compiled local support ahead of the dependency libraries.

`--check-setup` checks all pins, compiler version/digest and portable copied-runner setup without invoking Lean source compilation. Preparation tested that mode both from the working preparation and a clean extracted tree. The actual compiler SHA256 is recorded in `lean-setup-check.json`. Git HEAD checks do not attest cached olean contents; the existing compiler and dependency oleans are trusted. Neither the original audit nor this wrapper recursively rebuilds or rechecks the library's entire dependency closure. A fresh local `StaircaseSupport.olean` is required by the optional audit; no supplied support binary is included or trusted.

Optional paper rebuild: use the included exact `main.tex` and `references.tex` in a disposable directory with the manuscript's `support/build.py` and its documented TeX setup; this writes build receipts and is not needed for selected-byte verification. The six-page PDF and the parent's recorded full-page inspection remain frozen. `checks/build/receipt.json`, tool version, PDF metadata and compiler log are historical evidence, not a promise that different TeX versions reproduce identical PDF bytes.
