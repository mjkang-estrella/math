# Serial replay

Run `bash scripts/replay.sh` from an extraction under the assigned lane. This uses only the pinned read-only mathlib cache and Lean 4.34.1. The script creates lane-local tmp, logs and build directories. Builds are serial and resumable by source/olean timestamps; a new extraction has none. Each run gets a unique log name. The cap runner restricts affinity to CPUs 0 and 1, CPU time to 120 seconds, wall time to 140 seconds, managed RSS to 6 GiB, MALLOC_ARENA_MAX=2. Lean additionally uses -j1 -M3500 and warningAsError=true. RSS, rather than virtual address space, is monitored: a 6 GiB address-space cap prevents Lean from mapping the pinned cache even at low RSS. Initial failed attempts with that cap are retained.

The four modules build in order UlasSeries, UlasFinal, UlasChecks, UlasAudit; leanchecker runs serially on each. UlasAudit exports every imported environment declaration including generated names and opaque bodies' dependencies. The analyzer reconstructs the UlasFinal/UlasChecks import DAG, checks equality of the exported names and the modules' constNames plus extraConstNames, computes transitive axiom sets, and reports LOCAL versus upstream metadata. Upstream tactic/runtime unsafe declarations are reported, not mistaken for newly introduced proof dependencies. Every local declaration must be safe, total, have no implemented_by or extern, and use only propext, Classical.choice, Quot.sound. Endpoint assumptions remain explicit even if the axiom audit passes.

The source zip intentionally excludes builds, caches, receipts and logs. Extraction path safety is checked before extraction. The replay logs are outside the source zip in the delivered lane and in fresh-replay/logs. No network, repository mutations, or package rebuild is needed.
