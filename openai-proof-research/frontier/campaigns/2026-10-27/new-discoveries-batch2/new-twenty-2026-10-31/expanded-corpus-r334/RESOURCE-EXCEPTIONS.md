# Resource and process accounting

The first actual command was exactly the requested bootstrap command. bootstrap-receipt.json was preserved. Every subsequent shell job used timeout (30 or 140 seconds), Python -I -B and installed affinity to the first two ALLOWED CPUs, CPU limits (25 or 120 seconds) and AS 6 GiB before reading sources. Bootstrap has its own smaller limits. No mathematical computation/enumeration/search, Lean, CAS, solver, git or child agent was run. Local subprocesses were only pdftotext/pdftoppm source processing, inherited affinity and limits, and were synchronously waited/reaped. HTTP work used at most two threads, GET only, certificate verification on and redirects disabled. All fetch.py invocations completed with exit 0; each has a resource-*.json receipt. One new ScienceDirect journal403 was saved (error-body read capped at 1,000,000 bytes, so body SHA is the SAVED PREFIX, not whole response); it was not retried. All inherited denied routes were avoided.

Exceptions and honest limits: Early inline source-processing jobs did not all persist their own getrusage/UTC receipts. Their actual exits and tool wall times remain in the tool transcript; they are not reconstructed as invented measurements. All those inline jobs exited 0 except the attempted bs4 import, which exited 1 (ModuleNotFoundError) before reading source bodies. It was replaced with standard-library regex extraction, without any package install. One guessed arXiv ID 1803.03754 was unrelated; its title was read, retained as a failed source selection, and not used as evidence. The correct independently searched identifier 1803.07647 was subsequently read. No first receipt was overwritten.

ru_maxrss in resource-*.json is SELF process high water, in platform KiB; children_rusage is reaped-child accounting and NOT simultaneous group peak. No group/cgroup peak monitor was available. AS limits are per-process, not a cgroup guarantee. Managed web search and view_image do not expose full local group telemetry; no CPU/RSS/network-byte compliance claim is made for those managed tools. Thus limits were installed for every actual local job, but complete per-job/group telemetry is unavailable. Fetch resource receipt exit fields describe normal script completion; the tool transcript supplies true external timeout exits. No subprocess was left running. No unrelated global process scan/poll was performed.
