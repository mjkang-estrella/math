# Bounded strict replay

Use Lean 4.34.1 from /home/mj-kang/Documents/Dev/math/dlp-research/.tools/lean-4.34.1-linux/bin. The packet imports only bundled Std/Lean and its local modules. No network, package installation, shared write, SAT solver invocation, or other lane's script is needed.

Extract source-only.zip to a new directory inside this assigned round-4 lane. Check source-manifest.sha256 with sha256sum -c. Run bash replay.sh from that extraction. module-order.txt is the explicit serial module order. Each module gets one lean -M3500 -DwarningAsError=true invocation and one leanchecker MODULE invocation. Every Lean/checker/Python call must be wrapped by the included guard.sh with a distinct log label.

For chunked replay, run RESUME=1 BUDGET=600 bash replay.sh. BUDGET is elapsed wall seconds, checked between modules; a module already started may finish after the budget. A failure stops the driver. Resume checks a rolling digest of all source modules through the current module, its success stamp, and its compiled output. Changing an earlier module invalidates it and all later success stamps. Appending later modules does not invalidate prior modules. Only a compiler-and-checker success writes a stamp. replay-progress.json records the last completed module, while normalized-progress.json records only fully checked normalized replay modules and their exact next LRAT ID. No limit is raised on resume.

guard.sh supplies affinity to CPUs 0 and 1, CPU 120 seconds, wall 140 seconds, a 6 GiB process-group RSS watchdog, and MALLOC_ARENA_MAX=2. Temporary and cache variables point inside the extraction. It waits for its guarded child. Run only one heavy process at a time. Never call leanchecker without its explicit module argument.

AuditR4 checks metadata for declarations from every local module, including generated helpers, rejecting unsafe/partial metadata, compiler implementation overrides, extern declarations, local assumptions, and forbidden generated recursion helpers. Endpoint modules print their transitive axioms. Run the independent source scan as bash guard.sh source-scan python3 -I "$PWD/scan.py" "$PWD". The scan removes comments and strings before checking forbidden executable tokens; metadata checks separately cover declaration safety.

The delivered fresh-extracted directory and fresh-replay.log contain the actual extracted replay. Per-module logs, guard receipts and GNU time output remain there. module-times.json and results.json summarize only observed results. Development logs are separate under logs/. Some early elaboration attempts reused their labels; retained failures and the RSS-watchdog failure are disclosed in results.json, and are never counted as successful verification.

The source archive contains no compiled artifacts. It includes normalized.cnf, normalized-trimmed.json and their hash receipt for mechanical continuation. normalized.lrat remains outside the archive in this lane, copied byte-identically and hash-checked. The initial inherited archive hash and all 92 unchanged Lean source comparisons are recorded separately. No other lane's script was executed.

Final continuation frontier: 12,500 normalized additions. The formal source archive contains 443 verified modules, including six finite-check helpers for NReplay024. The original unfactored NReplay024 hit the fixed CPU cap, while the factored replacement passed. Its helpers split Boolean RUP checks from satisfaction proofs. This is a demonstrated way to keep later expensive chunks bounded without increasing a limit. The source-only packet stops at its conditional endpoint; adding the remaining suffix requires extending the module order and audit to include new sources, preserving existing verified modules. The full certificate data and unverified drafts are retained. Read the exact next step and LRAT ID from normalized-progress.json. Use python3 -I -B for future Python calls so bytecode writes are explicitly disabled even in isolated mode.
