# Resource and access audit

First actual shell command was exactly the requested timeout20 Python-I-B bootstrap. Its original receipt was preserved. Subsequent successful Python jobs installed <=2 allowed CPU affinity, CPU120 seconds and AS6GiB before reading/processing, with external timeout20 or140 seconds. Fetches use sequential public GET only,22-second request timeout and20MB bound. All completed synchronously. PDF text/render subprocesses inherited limits, had individual5/15-second timeouts, and were waited/reaped. No background job was started.

Resource telemetry limitations: bootstrap-receipt.json has measured self CPU/RSS. Fetch job tool outputs report wall and self high-water RSS (largest reported28164KiB); extraction reported56532KiB. These are self measurements, NOT sampled group/cgroup RSS. Aggregate group CPU/RSS telemetry was unavailable, so group compliance is not independently certified. Rendering and view_image service internal telemetry is unavailable. Managed web search service CPU/RSS limits and exact raw transport byte hashes are unavailable. Tool transcript is the per-job launch/completion log; not every early job wrote a separate machine resource receipt. This limitation is explicit, not backfilled with invented measurements.

Exceptions/errors: first HTML extraction imported absent bs4 before setting process affinity/rlimits and terminated immediately with ModuleNotFoundError (outer timeout20 held). That failed job did not attain the required per-process cap attestation; no source was read or file written by it. Replaced with standard-library HTMLParser, not dependency installation. Scanned2002 PDF pdftotext produced only formfeeds. OCR attempt rendered page1, then found no tesseract executable; pdftoppm had already been waited, no OCR process started. Pages1-5 were subsequently rendered in bounded jobs and visually read. One artifact-writing job stopped at missing mapping361913 after writing provenance and attempts; final job repaired the map and asserted exact20. No reservation changed. No live subprocess remains.

HTTP: receipts contain URL,UTC,GET,status/error,bytes/hash and final URL for each local fetch. The only HTTP failure was treeorder HTML404; it was not retried. Inherited blocked routes were not attempted. GitHub public HTML/raw files were used, never GitHub API. No POST, forms, consent, accounts, proxy/TLS bypass, cookies, JS or browser actions.
