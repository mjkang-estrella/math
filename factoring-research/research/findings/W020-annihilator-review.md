# W020 review: one interval budget for a supplied set of elements

**Disposition: accept the mathematical primitive and its amortization, with explicit representation and promise qualifications.** It really shares the search budget across all supplied elements, without a large-order first element, commutativity, randomness, integer factorization, or a group-order oracle. The exhausted-list output is actually the least common multiple of the supplied element orders. The recurrence, exponent amortization, and interval shrinking have direct prior art; no novelty or new complete factoring improvement is established. **Verified end-to-end improvement: NONE.**

## Decisions requiring parent intake

1. **Accepted:** exact order updates, no-growth bypass, singleton and unique-match returns, and the total `O(sqrt(W))` search budget. No assumption on the first element's order is needed.
2. **Accepted, sharpened:** before termination, `L = lcm(ord(g_1), ..., ord(g_j))` for the completed prefix. If the list is exhausted and the algorithm returns L, it is the exact set exponent, not just some common annihilator. This does not generally recover the designated h or the group cardinality.
3. **Representation repair:** effective multiplication, inversion, and equality alone do not supply the fast deterministic matching used in the bit bound. Require bounded-size canonical encodings, or a paid comparison/normalization mechanism compatible with group equality. Actual representation size and operation costs are independent parameters, not consequences of `log Hhi` under the general common-multiple promise.
4. **Promise repair for downstream wording:** a unique common annihilator for the supplied list need not annihilate arbitrary later samples. That extension is valid when the promised h is the group order, a global exponent multiple, or a common annihilator promised for the entire adaptive stream. The class-number application has the requisite global promise if its interval is proved valid.
5. **Prior-art correction:** Sutherland's Algorithm 8.2 already has the exact update; Kedlaya–Sutherland §4.2 already combines it with a divided group-order interval and unique-multiple termination. W020 supplies a clean factoring-free, deterministic common-multiple formulation, but this review establishes no priority for that formulation or improved asymptotic comparator.

## 1. Exact contract and invariant

Write `S_j = {g_1,...,g_j}` as a list, allowing repetitions, and

    e_j = lcm(ord(g_1), ..., ord(g_j)),     e_0 = 1.

The candidate set is

    C = {m in Z : Hlo <= m <= Hhi and g_i^m = 1 for every supplied i}.

The promise is `C != empty`, with some fixed designated h in C. It is not a promise that h is minimal or equals `|G|`. In general all that can be known about a non-unique designated h is its membership in C; returning L is an expressly allowed alternative.

The stronger inductive invariant is `L = e_j`. For an element g of order d,

    ord(g^L) = d/gcd(d,L),
    L * ord(g^L) = lcm(L,d).

These are facts inside the cyclic subgroup generated by g, valid in every finite group. If `beta=g^L=1`, then `d|L`, so marking g done leaves the invariant unchanged. Otherwise an exact small-order answer `r=ord(beta)` gives `L_new=lcm(L,d)`, which annihilates g, is a multiple of L, and preserves every earlier annihilation. This proof uses the orders only as mathematical objects; the algorithm need not compute d, any gcd with d, or a factorization.

Consequently L divides every common annihilator, including all of C and the designated h. Thus `1 <= L <= h <= Hhi`, and

    a=ceil(Hlo/L) <= h/L <= floor(Hhi/L)=z.

If `a=z`, C is contained in the singleton `{L*a}`. The nonempty promise proves both existence and equality to the designated h. If `ord(beta)>w=z-a` and two distinct integers k,k' in `[a,z]` killed beta, its order would divide `|k-k'| <= w`, a contradiction. The promise supplies at least one such k, namely h/L. The unique interval answer therefore identifies every element of C. No assumption that `[Hlo,Hhi]` contains the exact order of beta is used.

If the list is exhausted, L is `e_K`; it annihilates precisely the listed elements as required. For an **abelian** group generated by that list, L is the group exponent. It can be smaller than the cardinality. For a **nonabelian** group, killing a generating set does not imply killing every product of generators. For example, the two transpositions `(12),(23)` generate `S_3`, but their set exponent is 2; their product has order 3. This does not invalidate W020's supplied-element theorem.

An early unique return may occur before some supplied elements are examined. Its claim about those elements is conditional on the promise. Under only the supplied-list promise, consider a generator x of `C_6`, the single input `g=x^2`, and interval `[3,4]`. The large-order branch returns 3, but this does not kill a later sample x. Thus the parent's sentence about later samples needs the global-h qualification above. When h really is `|G|`, uniqueness recovers the actual group order and does apply to all future elements.

## 2. Boundaries and exact interval matching

Use width `W=Hhi-Hlo`, not the number `W+1` of integers. Require `1<=Hlo<=Hhi`; malformed input is rejected before searching. A computed `a>z` is incompatible with the promise and must not be treated as a singleton or passed to an integer square root. Every nonidentity search has `w>=1` because the singleton test precedes it.

The W018 bounded-order interface is reused: for radius `w>=1`, find the exact order if it is at most w, otherwise correctly report that it exceeds w, using `O(1+sqrt(w))` group operations and sortable list matching. Its distinct-baby/first-return convention prevents quadratic enumeration of duplicate matches. No ordinary-unit sampling theorem from W018 is used here. A returned `r=1` is impossible after `beta!=1`; accepting it would break the doubling argument.

For completeness, an exact realization of the terminating interval search is as follows. Set `m=ceil(sqrt(w+1))`. Store `(beta^i,i)` for `0<=i<m`. Generate

    T_j = beta^(-a-j*m),      0<=j<=floor(w/m).

A match `T_j=beta^i` gives `k=a+j*m+i`. Keep it only if `k<=z`. Every offset in `[0,w]` has exactly one representation `j*m+i` in these ranges, so both interval endpoints are included. Since `ord(beta)>w` and `m-1<=w`, the babies are distinct. Thus each giant has at most one baby match; filtering the final partial block is essential. Compute the initial shift by binary powering and an inverse, and subsequent giants by multiplying by `beta^(-m)`. The shift costs `O(log Hhi)` group operations, once, and is not free.

Hand-worked boundary witnesses below are proof examples, **not executed trials**:

- `K=0`: if the interval is a singleton return its value; otherwise returning L=1 is valid for the empty set. Neither output identifies a group order from no information.
- `W=0`: return Hlo conditional on the promise, even if Hlo is a huge binary integer. No search runs. If Hhi=1, the promise forces every supplied element to be the identity.
- Arbitrarily many identity elements, or elements killed by the current L, incur powering/equality work only. Repetitions never require another search after that element has been annihilated.
- For a generator of `C_5`, intervals `[10,14]`, `[6,10]`, and `[8,12]` all have width 4 and uniquely return 10: lower endpoint, upper endpoint, and interior respectively. The promised annihilator can be a proper multiple of the element or group order.
- For the same generator, `[5,10]` has width 5 and two endpoint matches. `r=w` belongs to the small-order branch; changing `>` to `>=` in the uniqueness test would be wrong.
- For a generator of `C_2` and `[5,7]`, the small-order update gives L=2 and the narrowed singleton gives `L*a=6`, not L=2. An implementation that returns L for the singleton is wrong.
- For independent generators of `C_2 x C_2` and `[3,6]`, the first search sets L=2, and the second element is identity-powered. The exhausted-list output 2 is smaller than the cardinality 4; possible designated h values include 4 and 6. No exact-cardinality conclusion follows.
- For the three coordinate generators of `C_2 x C_3 x C_5` and `[1,120]`, the search widths are 119, 59, and 19; the successive L values are 2, 6, and 30. Inserting any number of already-annihilated elements between these stages adds no search. This illustrates multiple growth stages without a large first order.
- A generator of `C_3` with `[4,5]` violates the promise and has no interval match. It must not produce a fabricated integer.
- For a generator of `C_3` and `[3*2^t,3*2^t+1]`, the search radius is just 1 but the initial interval shift has a `Theta(t)`-bit exponent. The logarithmic powering term remains necessary.

## 3. Promise checking versus certifying the group order

Optional verification of all `g_i^v=1` for a unique output v turns its membership in C into a checked assertion, at an additional `O(K log Hhi)` group-operation cost. Test interval membership as well. This does not certify `v=|G|`: in `C_2 x C_2`, every element is killed by 2, while the cardinality is 4. A singleton interval `[2,2]` therefore satisfies the common-annihilator promise but is a false group-order interval, even with a full generating set and complete powering verification.

The stronger prefix invariant also makes an exact common-promise consistency version possible at the same asymptotic cost. On a singleton or unique-match return, verify all supplied elements; no match or a failed verification rejects the promise. On list exhaustion, L is the exact set exponent, so C is exactly the multiples of L in the original interval. Recompute a,z; existence is `a<=z`, with witness `L*a`. Verifying `g_i^L=1` alone is a statement about L, not an interval-membership test on L. In W020's actual small-order path, existence is automatic: an update has `L_new=L*r<=L*w<=W`, hence an interval of width W contains a multiple of L_new. The explicit final check remains a useful total-interface convention.

None of this validates an analytic claim that the class number lies in the interval. That is an external promise whose proof or failure probability must be paid separately. Also, the pair `(v, beta^v=1)` by itself is not a succinct certificate of uniqueness. Uniqueness follows from the exact completed search and the retained invariant; an independent verifier must check that evidence or repeat the paid search.

## 4. Total operations, bit costs, and memory

Let `n=ceil(log2(Hhi+1))>=1`. Number only the nonidentity search stages, starting at j=0. Earlier completed searches multiply L by at least 2; identity-powered traffic leaves L fixed. Hence

    L_j >= 2^j,
    1 <= w_j <= W/L_j <= W/2^j,
    sum_j sqrt(w_j) <= sqrt(W)/(1-1/sqrt(2))  (W>=1).

The sum is below `3.415*sqrt(W)`. There are at most `1+floor(log2 W)` searches when W>=1, also at most K. The terminal interval BSGS occurs at most once; charge its square-root term to the same terminal stage and its shift separately. Ceilings and the constant work per stage are absorbed because `w_j>=1`. For W=0 there are no searches. The total group-operation bound, allowing all-output verification, is

    O((K+1)*n + sqrt(W)).

This includes each powering by L, all bounded searches, the one possible interval shift, inverse/stride setup, and verification. It implies the parent's A3 with the standard `1+log Hhi` convention. Table matching has a separate comparison cost; it is not an oracle hidden in this operation count.

Here is a conservative bit realization, with all additional parameters exposed. Let I be the total supplied input-description length, b bound each normalized group encoding used during the computation, and c_G bound the bit cost of multiplication, inverse, normalization, and equality on those encodings. Assume each element has a canonical sortable key of at most b bits. With elementary binary integer arithmetic, sorted lists, merge matching, and reusable workspace, a sufficient bound is

    O( I
       + ((K+1)*n + sqrt(W))*c_G
       + (K+sqrt(W)+1)*(n^3 + log(K+2))
       + (sqrt(W)+1)*(b+n)*n ).

This is deliberately loose in logarithmic factors. Binary powers use O(n) group operations; no loop runs for the numerical exponent. L, a, z, r, and all retained exponents have O(n) bits. Temporary overshoot indices and integer products have O(n) bits as well. Divisions, ceilings, integer square roots, updates, and endpoint filtering are charged. Sort/merge traffic comprises `O(1+sqrt(W))` total table records, each with a b-bit key and O(n)-bit index; comparison sorting costs `O((1+sqrt(W))*n)` comparisons and pays record movement. The `log(K+2)` allowance covers ordinary list/index bookkeeping; input parsing is in I. No constant-time hashing is assumed.

Thus the advertised soft envelope is valid **relative to paid representation costs**. It becomes `O~((K+sqrt(W)+1)*poly(n))` in bits when b, c_G, and the relevant group/input description costs have the corresponding polynomial bounds. Mere effectiveness is not such a bound. In particular, a small common annihilator need not bound `log|G|` or the element encoding length: `G=(C_2)^d` has global exponent 2 and may have arbitrarily large d. Its bit costs cannot be charged solely to `log Hhi` if `[Hlo,Hhi]=[2,2]`.

Nor does equality alone justify sorting. Distinct representations of the same group element need not compare equal as strings. An efficient canonicalization, equality-compatible total ordering, or another explicitly costed matching data structure is required; the naive all-pairs equality fallback may use Theta(W) comparisons. This is a repair to the general effective-group interface, not a difficulty specific to class groups with canonical reduced forms.

Maximum temporary storage is `O((1+sqrt(W))*(b+n))` bits plus the integer/group-operation workspace and `O(log(K+2))` bookkeeping, excluding the read-only supplied input. Do not store every old table. If input elements cannot be reread and later verification is desired, their storage is additional. Acquisition, random-bit generation, mixing, and adaptive element-production costs are outside this supplied-input bound and must be added. Adaptivity does not change the amortization for a single group and a common interval promise valid for every queried element.

## 5. Exact prior-art overlap and equal-input comparison

Only primary sources support the following attribution. Search hits from secondary sources were not used as mathematical authorities. Full files were retained; only the portions named in the read scope were audited. This is not an exhaustive priority search.

**Schoof (1982), §3, printed pp.247–250; Algorithm 6.4, pp.270–272.** The class-group construction searches a class-number interval for an order multiple, extracts exact orders by factoring, and refines later work using known divisibility. Page 248 explicitly powers later forms and divides the interval to reduce search; its discussion describes a favorable first large contribution as usual, not universally guaranteed. Algorithm 6.4 charges repeated per-form searches and obtains the GRH-conditional `N^(1/5+epsilon)` bound. This directly establishes the class-group antecedent, without asserting that its printed algorithm contains W020's exact factoring-free dichotomy. [Primary scan](https://www.mat.uniroma2.it/~schoof/mcpaper.pdf).

**Sutherland (2007), Algorithm 8.2 and Proposition 8.7, printed p.134; supporting pp.130,133–136.** The supplied-set algorithm uses exactly `alpha=beta^E; E<-E*ord(alpha)`. Its stated scope includes nonabelian groups, and its order-computation bound is `T(lambda(S))+O(K log lambda(S))`. Identity bypass and dynamic reuse are explicit in Algorithm 8.1/Theorem 8.9. The source's black-box definition, pp.19–20, uses unique bit-string identifiers. This is direct prior art for the recurrence, no-large-first-element principle, and amortized set computation. [Primary thesis](https://math.mit.edu/~drew/sutherland-phd.pdf).

**Kedlaya–Sutherland (2008), §4.2, PDF pp.6–7.** This goes beyond generic exponent accumulation: it searches the divided interval `[M0/E,M1/E]` for a powered element, updates E, and uses uniqueness of a multiple in the original interval. It discusses both factoring an annihilator to recover exact order and searching the rest of the interval to prove uniqueness. These are direct interval-aware antecedents. The source prints `|G|=E` after its unique-multiple condition; the correct general inference is that `|G|` is that unique multiple of E, which need not be E itself. W020's `L*a` handles this correctly. [Primary paper](https://math.mit.edu/~drew/ComputingLSeriesOfHyperellipticCurves.pdf).

For an equal-input comparison, supply the comparator with exactly the same group representation, K elements, interval, and nonempty common-multiple promise. The naive `K*sqrt(W)` baseline is too weak: established exponent accumulation must be allowed. Unrestricted exact-order accumulation alone gives a bound in the set exponent rather than the narrow interval width, so it is also not enough simply to cite Proposition 8.7 as though it already states W020 verbatim. Likewise, factoring the large interval annihilator is not free when W is tiny relative to Hhi.

There is, however, a direct factoring-free completion of the established interval-search strategy with the **same** bound. The following is a reviewer derivation from the elementary list method and exponent accumulation, not a claim that every detail is printed in a cited source:

1. After the same identity test, form babies `beta^i`, `0<=i<m`, with `m=ceil(sqrt(w+1))`. A first positive return to 1 supplies the exact small order immediately.
2. Otherwise the babies are distinct. Enumerate the same shifted giants and retain the two smallest admissible interval matches, if present. There are at most `floor(w/m)+1` matches, since each giant matches at most one baby; no collision Cartesian product is enumerated.
3. No match means inconsistency. One match identifies the unique promised integer. If there are at least two matches, their positive difference is exactly `ord(beta)`: they are consecutive multiples of that order within an interval containing every integer between them. Update L by that difference and continue.

Every nonterminal update is exact and multiplies L by at least two; its order is at most w. The same geometric proof gives `O(sqrt(W))` total search work, plus the same powering, shifting, and encoding charges. Here an initial interval shift may occur at several stages, costing at most `O(min(K,n)*n)` group operations in total; this fits the existing `O(K*n)` allowance. The method needs no supplied factorization, randomness, large-order first sample, or access to the hidden h. Thus the interval-aware prior-art framework, completed with elementary exact collision handling, matches the claimed soft envelope on equal inputs. W020 is a valid useful formulation; a new asymptotic advantage over the appropriate comparator is not established.

## 6. Factoring consequence and unresolved work

For one class group, a proved interval containing the class number and a paid supplied generating set suffice to share the annihilator search as claimed. The group's abelianness then turns the exhausted-list L into its exponent; it need not become its class number. The accepted W019-B odd-part/pivot interface can consume a verified annihilator for each processed element. Later growth does not invalidate an earlier annihilation or that interface. No W019-B probability or cancellation proof is rerun here.

With the parent's conditional width `W~sqrt(N)/sqrt(B)`, the search term is `sqrt(W)~N^(1/4)*B^(-1/4)`. Balancing it with B gives `B^5=N` and exponent 1/5. Removing a repeated generator-search factor does not improve that exponent; under a polylogarithmic generator count it was already hidden in the soft bound. A global performance statement must still pay interval construction and precision, justify the analytic tail, acquire a generating set or useful fresh samples, and prove the appropriate full-input extraction/success claim. This audit supplies none of those absent ingredients and does not import ordinary-unit sampling into class groups.

Separate discriminants have separate common annihilators and generally separate class numbers. Knowledge `L_D | h(D)` does not imply `L_D | h(D')`. No cross-discriminant sharing follows without an additional proved relation and its acquisition cost.

**Accepted scope:** deterministic common-annihilator/set-exponent-or-unique-integer computation on supplied inputs, with the explicit representation model and the geometric cost proof. **Repaired scope:** canonical matching/bit parameters, nonabelian generator language, early-return verification and future-sample promise. **Rejected extrapolations:** automatic group-order recovery, a complete factoring algorithm, an improved exponent, free sampling/generation/tails, cross-discriminant reuse, or established novelty. The next result that could change the factoring conclusion must supply cheaper paid interval information or another useful-element source, together with coverage/success and an equal-input comparison; another abstract cancellation audit would not discharge those obligations.
