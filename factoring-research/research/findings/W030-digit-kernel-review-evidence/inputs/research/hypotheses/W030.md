# W030: separable root acquisition with uncarried digit products

Parent constructive derivation, 2026-10-08 local. No numerical run yet.
**Verified complete factoring improvement: NONE.** The new computation is
a small representation of the full root family and its carry intervals,
not an assumed fast product on that representation.

## 1. Replace pairwise root charts by two root tables

Import one W022 valuation stratum: Q=ell^L=M_t^2, ell odd prime,
gcd(ell,N)=1, and signed integer ranges of ell-unit u and v with sizes
at most U,V. The true covered S=up+vq satisfies |S|<=W and
S^2=4Nuv modulo Q. W024 supplies the public prime schedule and nonzero
residue filter. This construction changes the representation inside a
stratum; it does not change or assume a factor-dependent cover.

Find a nonsquare delta modulo ell and use the same integer lift modulo Q.
Partition v by its square class epsilon in {0,1}, so delta^(-epsilon)*v
is square modulo ell. For this class retain exactly those u for which
4N*delta^epsilon*u is square modulo ell. Acquire one root per coordinate:

    A_u^2 = 4N*delta^epsilon*u mod Q,
    B_v^2 = delta^(-epsilon)*v mod Q,
    0 <= A_u,B_v < Q.

Both radicands are units. A root modulo the small public ell lifts uniquely
after its initial sign is selected. Then +/- A_u*B_v are exactly the two
roots of 4Nuv modulo Q. Invalid square-class combinations have no roots
and are absent. The epsilon partition costs only a constant number of
tables; Hensel acquisition, labels and storage cost (U+V)*polylog(N), with
the actual ell preprocessing charged. For the public polylogarithmic ell
schedule this is still polynomial logarithmic overhead per table entry.

This improves the representation size in a balanced stratum from a list
of UV pair roots or H^2 separately acquired chart data to O(U+V) root data.
It does NOT claim that every existing H^2 chart construction required
H^2 independent root lifts: some acquisition could already be shared.
No UV coefficient arrays are emitted by this representation.

Using the unreduced integer A_u*B_v directly would enlarge the carry range
by Q, while reducing it modulo Q at each pair would recreate UV records.
The next operation avoids both of those particular costs.

## 2. Do not propagate carries in the product of the root digits

Write the acquired roots in base ell:

    A_u=sum_(i=0..L-1) a_(u,i)*ell^i,
    B_v=sum_(j=0..L-1) b_(v,j)*ell^j,
    0<=a_(u,i),b_(v,j)<ell.

Use the uncarried truncated convolution as an INTEGER root representative:

    R(u,v)=sum_(i+j<L) a_(u,i)*b_(v,j)*ell^(i+j).

The discarded terms in A_u*B_v are multiples of Q. Hence R=A_u*B_v
modulo Q, and R^2=4Nuv modulo Q. There is no coefficientwise or
pointwise remainder in this definition. For all input digit vectors,

    0<=R <= (ell-1)^2 * sum_(k=0..L-1)(k+1)*ell^k
          <= L*(ell-1)*(Q-1) < L*(ell-1)*Q.

The second inequality uses (k+1)<=L and the geometric sum. Therefore a
single symmetric integer carry interval

    |tau| <= ceil(W/Q)+L*(ell-1)

contains the tau of every covered S=sign*R+Q*tau. The overhead is
O(ell*log_ell Q), rather than Q or a large coordinate power. Padding is
intentional and must be paid. This works for every table pair, not just
a typical root, and retains signed v and both root signs.

The complete exponent is now the explicit bilinear expression

    E(u,v,tau)=u+N*v
       -sign*sum_(i+j<L) ell^(i+j)*a_(u,i)*b_(v,j)-Q*tau.

Its arithmetic circuit uses O(L^2) digit products per supplied pair;
the point of the representation is that it need not be expanded into
all UV values before selecting an aggregate evaluation algorithm.
Operand widths are O(log(U+N*V+ell*L*Q+W)), not unit-cost large integers.

## 3. Retain the nonzero-exponent filter without pair enumeration

Modulo ell, R=a_(u,0)*b_(v,0). Partition each table by its low digit
(and square class and sign). In each resulting Cartesian table pair,

    E = u+Nv-sign*a_(u,0)*b_(v,0) mod ell

is constant: A_u^2 fixes u modulo ell and B_v^2 fixes v modulo ell.
Test that residue once and discard the entire block if it is zero.
There are at most O(ell^2) block labels, and table entries can be shared
by index rather than recopied for each partner. Every retained E is a
nonzero integer, even with padded carries. W024's covered witness for
an eligible prime is retained, since its exponent residue is unchanged.
The selected root sign, digit tables, blocks and carry bounds are public
and independent of the random unit base alpha. Freeze them during W020
localization; restricting lists or intervals preserves the same product.

## 4. What this does and does not buy

In the balanced top stratum U,V on the scale sqrt(M), Q=M^2 and
W on the scale sqrt(N*M), setup and representation now cost
sqrt(M)*polylog(N). The common carry length is at most a constant times

    1 + sqrt(N)/M^(3/2) + ell*log_ell(M).

The existing explicit-anchor consumer still costs

    O~(M + sqrt(M*T)).

Its M term remains and its one-fifth cost envelope is unchanged. In
unbalanced strata U+V can itself approach M; those ranges have not been
made free. A complete theorem must still cover every such range and
preprocessing case.

The new target is a supplied bilinear digit kernel, not a quartic
polynomial on short integer intervals. Its input has O((U+V)L) digits;
outputting all E values would defeat the intended saving. An aggregate
cost on the scale U+V+sqrt(UV*T), if actually implemented, would give a
balanced bookkeeping target M=N^(1/3), exponent 1/6 up to logarithms.
This is only a cost target: no such product algorithm is supplied here,
and it is not a claimed all-input factoring bound.

## 5. An explicit attempted consumer and its obstruction

For one row block I, define the actual polynomial

    F_I(Y,X_0,...,X_(L-1))
       = product_(u in I)(1-alpha^u * Y * product_i X_i^(a_(u,i))).

At a column v and carry tau, substitute

    X_i=alpha^(-sign*sum_(j<L-i) ell^(i+j)*b_(v,j)),
    Y=alpha^(N*v-Q*tau).

This identity computes the required row-block product. Inverse powers
use the checked unit alpha. Column coordinates can be acquired in O(VL)
small-base powering operations using weighted digit suffixes, plus binary
exponent setup; they do not require UV entries. But F_I has L+1 variables.
For b rows its dense box has at most
((ell-1)*b+1)^L*(b+1) slots. That is too large when L grows with log N.
The alternative subset expansion has at most 2^b terms, each carrying
O(L log(ell*b)) exponent bits. A literal enumeration of all 2^b subsets
can keep this work polynomial in N only for b=O(log N), so that proposed
implementation does not save a fixed power in
the number of row blocks. Even those sparse evaluations still need a
priced algorithm; sparsity alone does not give fast multipoint evaluation.

The bilinear coefficient matrix C_(i,j)=ell^(i+j) for i+j<L and zero
otherwise has full rank L over Q (reverse columns to see a triangular
matrix with diagonal ell^(L-1)). Consequently a constant number of
LINEAR digit features cannot reproduce this bilinear form for arbitrary
digit vectors. This is not a lower bound for the actual root tables,
nonlinear features, sparse circuits or factoring.

The useful next question is whether this triangular digit interaction
admits an aggregate norm, divide-and-conquer or other product computation
without expanding either pairs or subsets. Carry propagation is already
unnecessary here; a proposed fast consumer must address the product itself.

## 6. Decisive validation

Independently audit square-class coverage, uncarried height, low-digit
filter partition, signed endpoints and frozen-family localization.
One optional preregistered <=60-second, <=20,000-event certificate may
compare roots, coverage and the exact block-polynomial identity on a
small fixed suite, retaining all failures. Such a check cannot test the
fast multivariate theorem or establish the missing aggregate complexity.
No shared solver or Lean implementation is requested before the audit.
