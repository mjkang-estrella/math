# H003 — Factor-sum residue compression gate

Status: preregistered diagnostic, parent-owned, no novelty claim.

## Mechanism

For odd N = pq, the sum s = p + q makes s² − 4N an integer square. For an odd
prime ell not dividing N, retain residues s modulo ell for which s² − 4N is a
quadratic residue or zero. Combine the allowed sets by CRT over distinct primes.
Hypothesis to assess: can storing these local constraints compactly by itself
justify a fixed-exponent reduction in enumerating candidate factor sums?

The underlying hyperbolic/factor-sum sieve is known prior art:
[Hittmeir, Integer factorization as subset-sum problem](https://arxiv.org/abs/2205.10074).
This diagnostic does not claim a new sieve or refute accelerated interval-query
methods. The exact bottleneck is constructing or querying useful global candidates.

## Predictions and falsifier

1. For ell not dividing N, the local cardinality is
   (ell + Legendre(N, ell))/2. Test every nonzero N residue for odd primes <= 43.
2. CRT output cardinality equals the product of local cardinalities. Explicitly
   materialize for primes through 17 and N in {10403, 1022117}; compare with direct
   residue filtering for the first five primes only (modulus 15015).
3. For any k distinct odd primes and product M, the global set has at least M/3^k
   elements. Since M >= (k+2)!/2, k/log(M) tends to zero along any unbounded such
   family, and the materialized set has size M^(1-o(1)). This rules out a uniform
   fixed-power saving from *enumerating this complete residue set* alone.

Reject the explicit-set fixed-exponent argument if these identities hold and the
elementary derivation is independently reviewed. Do not infer a lower bound for
all representations or all interval-query algorithms. No fit is a theorem.

## Experiment

Run `python3 research/experiments/H003/sieve_cardinality.py` with a 60-second shell
timeout. All numerical constants are in the script; no RNG, no factor oracle.
The script records local tests, explicit CRT construction work/cardinalities,
direct-check equality, source hash, and counts-only bounds through 64 primes.
Counts-only rows do not claim to have enumerated huge sets or factored N.
Output is `research/experiments/H003/result.json`; preserve the first run unchanged.

This is a combinatorial primitive diagnostic, not a new splitter registered in
the benchmark. CRT merge counts omit big-integer cost, list allocation/sorting and
memory accesses; those omissions cannot improve the enumeration lower bound.
Avoid expanding Lean infrastructure for this gate. A finite-field cardinality
proof would need additional algebra support; request a mathematical review first.
